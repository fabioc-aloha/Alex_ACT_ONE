## Important findings before cleanup

1. **The detector can report clean for missing or changed evidence.** Synthetic counter-tests of [skills/proactive-awareness/scripts/check-session-artifacts.cjs](../../../../skills/proactive-awareness/scripts/check-session-artifacts.cjs) returned `clean` when the manifest named a missing repository copy and when the original session file changed after recovery. It trusts manifest session/path/hash records without checking destination bytes. Its malformed-manifest catch also hides the manifest error. Retain and repair; do not treat its current output as a custody proof.
2. **Authentication verification is too weak.** [skills/git-workflow/scripts/check-git-auth.cjs](../../../../skills/git-workflow/scripts/check-git-auth.cjs) treats helper text and an account-name match as readiness; it does not exercise the configured helper or verify authenticated identity/access. It also conflates repository owner with login identity (organizations/collaborators), processes arbitrary HTTPS hosts as GitHub, and writes the helper in multiple steps without rollback. These are source-inspection findings, not a vulnerability assessment or live destructive tests.
3. **The local recovery helper is maintainer tooling.** [scripts/recover-local-artifacts.mjs](../../../../scripts/recover-local-artifacts.mjs) has task-specific rawfeed/snapshot exclusions and regex-based screening; it requires reviewed overrides for legitimate synthetic fixtures. Do not promote its exclusions into a universal classifier. Keep its tested custody value with operations history, or consolidate reviewed common mechanics without losing tests.
4. **The old importer and verifier are coupled.** [scripts/session-recovery.mjs](../../../../scripts/session-recovery.mjs) contains hard-coded historical session IDs as well as the useful archive verifier and shared `sanitizeText`. The other recovery helper and both test suites import it. Preserve/extract the verifier and shared sanitization before considering importer removal.
5. **Historical evidence is actually shipped.** Read-only filesystem inspection of the loaded `0.9.3` cache found both the recovery history and manifest. Moving files to an `archive/` folder does not, by itself, stop a source-based plugin install from fetching them. A lean release requires a separately verified packaging/custody design, not merely a folder rename.
6. **An empty-file count and exact duplicate hash are stronger than filename similarity.** Exact duplicates are marked below with a retained canonical row. Different assessments with zero findings are PRUNE candidates, not falsely labelled byte-identical. Failed browser receipts remain failures, even when their filenames say final or release.

## What was actually inspected

Every historical file was read and hashed. Authored reports and helper implementations were read; the three PNGs were viewed. Existing live guidance and consumers/tests were checked. This is a retention review, not a fresh rerun of historical tests, proof of old numerical prose, web fact-check, or complete security audit. Old helpers were not executed.

The frozen archive integrity command passed for all 220 files and 9,318,096 recovered bytes. Synthetic detector counter-tests used disposable fixtures and did not change project input files. Read the [sortable file-by-file CSV](files.csv) for hashes, observed evidence, rationale and removal dependencies.

The [report renderer](render-review.mjs) preserves the explicitly reviewed selections and checks exact input scope, file hashes, counts and row coverage. Its rendering is deterministic; the recommendations remain human-review proposals, not an automatic deletion classifier. It only writes these report outputs.

1. Preserve the source/tag recovery point and inventory. Do not rewrite Git history or remove external originals as part of pruning.
2. First remove only approved DELETE rows, retaining duplicate mappings, empty-attempt facts and CI run IDs in the custody record.
3. Decide which PRUNE rows contain any uniquely cited fact. Keep a concise receipt/excerpt where needed; archive the selected reports, failure-to-fix evidence, live traces and final receipts.
4. Update the manifest, retained indexes/links, historical-status notes and inventory tests coherently. The current strict verifier intentionally fails if any listed file is simply removed.
5. Repair the live detector/auth checker in a separate scoped change, then prove missing/changed/ignored/unsupported cases fail explicitly. Do not delete the safeguards because their first implementation is incomplete.
6. Only if requested, verify a new source/Mall release and installed package. No release or installed-cache change is authorized by this review.
